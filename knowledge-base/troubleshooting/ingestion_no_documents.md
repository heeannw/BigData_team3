# TS-006 문서 적재 시 NO_DOCUMENTS 오류가 나오거나 검색 결과가 없을 때

## 증상
- 문서 적재 실행 결과가 `success: false`, `error: NO_DOCUMENTS`로 반환된다.
- 적재는 성공했다고 나오는데 질문하면 관련 문서가 검색되지 않는다.
- 청크 수가 0이거나 예상보다 적다.

## 영향 범위
- 지식베이스 전체. 문서가 적재되지 않으면 챗봇은 근거 없이 답변을 보류한다.

## 가능한 원인
1. `knowledge-base/` 폴더가 비어 있거나 문서가 잘못된 위치에 있다.
2. 지원하지 않는 파일 형식이다(현재 `.md`, `.txt`만 지원).
3. 문서를 추가한 뒤 재적재를 하지 않았다.
4. 임베딩 모델이 문서 적재와 질문 검색에서 다르다(TS-005 참조).
5. 문서의 섹션 제목이 모호하거나 질문 표현과 문서 표현이 너무 다르다.

## 우선 점검 순서
1. `knowledge-base/<카테고리>/` 아래에 `.md` 또는 `.txt` 파일이 있는지 확인한다.
2. 적재 스크립트를 실행하고 응답의 `documentCount`, `chunkCount`를 확인한다.
   ```bash
   bash scripts/ingest-documents.sh
   ```
3. 응답의 `documents` 목록에 추가한 문서가 있는지 확인한다.
4. Qdrant 컬렉션(`knowledge_base`)에 데이터가 들어갔는지 확인한다.

## 조치 방법
1. 문서를 올바른 카테고리 폴더에 `.md` 또는 `.txt`로 저장한다.
2. 문서를 추가하거나 수정할 때마다 적재 스크립트를 다시 실행한다.
3. 검색이 안 되면 문서의 `## 증상` 섹션에 사용자가 실제로 쓰는 표현을 추가하고 재적재한다.

## 성공 확인 방법
- 적재 응답이 `success: true`이고 `chunkCount`가 0보다 크다.
- 문서 내용과 관련된 질문을 했을 때 해당 문서가 검색된다.

## 예방 방법
- 문서 하나에는 하나의 주제만 담고, 제목과 섹션명을 의미 있게 작성한다.
- 문서 추가·수정 후 재적재를 작업 절차에 포함한다.
