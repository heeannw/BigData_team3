# TS-005 Ollama 모델을 찾을 수 없거나 응답이 느릴 때

## 증상
- 임베딩이나 답변 생성 시 모델을 찾을 수 없다는 오류(예: model not found)가 발생한다.
- 첫 질문의 응답이 매우 느리고 이후에는 빨라진다.
- 검색은 되는데 결과가 이상하게 나온다.

## 영향 범위
- 문서 임베딩, 질문 임베딩, 답변 생성.

## 가능한 원인
1. 폐쇄망에 모델 파일을 반입하지 않았거나 올바른 위치에 두지 않았다.
2. 워크플로우의 모델 이름과 설치된 모델 이름(태그 포함)이 다르다.
3. 문서 적재와 질문 검색에 서로 다른 임베딩 모델을 사용했다. 벡터 공간이 달라 검색이 맞지 않는다.
4. 첫 호출 시 모델을 메모리에 올리는 시간이 포함되어 느리다. 이는 정상 동작이다.
5. 메모리 부족 또는 CPU 환경(GPU 없음)에서의 속도 한계.

## 우선 점검 순서
1. 설치된 모델 목록을 확인한다.
   ```bash
   docker compose exec ollama ollama list
   ```
2. 워크플로우 노드의 모델 이름을 확인한다. 임베딩 모델은 문서 적재 워크플로우와 질의응답 워크플로우가 같아야 한다(예: `bge-m3:latest`).
3. `offline-assets/model-files/`에 모델 파일이 있는지 확인한다.

## 조치 방법
1. 인터넷이 되는 PC에서 `prepare-offline` 스크립트로 모델을 받아 `offline-assets/model-files/`에 두고 폐쇄망 PC로 반입한다.
2. 인터넷이 가능한 환경이라면 필요한 모델을 직접 내려받는다.
   ```bash
   docker compose exec ollama ollama pull bge-m3
   ```
3. 노드의 모델 이름을 설치된 모델과 동일하게 맞춘다.
4. 임베딩 모델을 바꿨다면 문서를 전체 재적재한다.
5. 첫 호출이 느린 것은 모델 로드 시간이므로 시연 전에 한 번 미리 호출해 둔다.

## 성공 확인 방법
- `ollama list`에 필요한 모델이 표시된다.
- 임베딩 생성과 답변 생성 노드가 오류 없이 실행된다.

## 예방 방법
- 임베딩 모델은 프로젝트 중간에 변경하지 않는다.
- 설치 후 헬스체크로 모델 존재 여부를 확인한다.
