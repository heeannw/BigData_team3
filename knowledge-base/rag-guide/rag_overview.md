# RG-001 RAG 구조와 이 시스템의 동작 흐름

## RAG란
RAG(Retrieval-Augmented Generation)는 LLM이 기억에 의존해 답하는 대신, 먼저 등록된 문서에서 관련 내용을 검색하고 그 내용을 근거로 답변을 만드는 방식이다. 이 시스템은 등록한 내부 문서 범위 안에서만 답하도록 설계되었다.

## 문서 적재 흐름
1. `knowledge-base/` 문서를 읽는다.
2. 제목(`#`, `##`) 단위로 섹션을 나누고, 긴 섹션은 800자 크기(100자 겹침)의 청크로 나눈다.
3. Ollama의 임베딩 모델 `bge-m3`가 각 청크를 1024차원 벡터로 바꾼다.
4. 벡터와 메타데이터를 Qdrant 컬렉션 `knowledge_base`에 저장한다.

## 질의응답 흐름
1. 사용자가 질문을 입력한다.
2. 질문을 같은 임베딩 모델로 벡터로 바꾼다.
3. Qdrant에서 질문과 가장 비슷한 청크를 검색한다.
4. 검색된 청크와 질문을 함께 LLM(`qwen2.5:3b`)에 전달한다.
5. LLM이 검색된 내용을 근거로 답변을 만들고, 사용한 문서의 출처를 함께 보여 준다.

## 요청 유형
- `operation`: 운영 방법 문의. 관련 문서를 검색해 절차를 안내한다.
- `diagnosis`: 장애 진단. 오류 상황이나 로그를 바탕으로 원인 후보, 점검 항목, 조치를 구조화한다. 장애 문서(`troubleshooting`)로 검색 범위를 좁힐 수 있다.

## 응답 구성
응답에는 `success`, `requestType`, `answer`, `diagnosis`, `sources`, `responseTimeMs`가 들어 간다. 출처(`sources`)에는 문서명, 카테고리, 섹션, 청크 ID가 표시된다.

## 근거가 없을 때
검색 결과에 답이 없거나 근거가 부족하면 추측하지 않고 "제공된 내부 자료에서는 확인할 수 없습니다."라고 답하며 출처는 비워 둔다.

## 일반 LLM과의 차이
- 일반 LLM은 학습한 일반 지식으로 답하므로 우리 환경에 맞지 않는 내용을 지어낼 수 있다.
- RAG는 등록한 문서를 근거로 하므로 출처를 확인할 수 있고, 문서에 없는 질문은 답변을 보류한다.

## 주의사항
- 문서 적재와 질문 검색에 같은 임베딩 모델(`bge-m3:latest`)을 써야 한다.
- 답변 품질은 등록한 문서의 품질과 범위에 좌우된다.
