# RG-002 청크 크기·오버랩 조정과 검색 품질 가이드

## 목적
문서 분할 설정과 문서 작성 방식이 검색 품질에 미치는 영향을 이해하고 조정한다.

## 현재 설정
- `CHUNK_SIZE` 기본 800자, `CHUNK_OVERLAP` 기본 100자(`.env`에서 조정).
- 문서는 먼저 `#`, `##` 제목 단위의 섹션으로 나뉘고, 한 섹션이 800자를 넘으면 문단 단위로 다시 분할된다.
- 섹션 제목 경로가 `section`으로 저장되어 출처 표시에 쓰인다.
- 임베딩할 때는 문서 제목과 섹션명을 본문 앞에 붙여 검색 정확도를 높이고, 저장되는 `content`에는 본문만 들어간다.

## 청크 크기를 정하는 기준
- 너무 작으면 문맥이 끊겨 답변 근거가 부족해진다.
- 너무 크면 한 청크에 여러 주제가 섞여 검색 정확도가 떨어지고, LLM에 전달할 내용이 길어진다.
- 겹침(오버랩)은 청크 경계에서 문장이 끊길 때 문맥을 이어 주는 역할을 한다.

## 검색이 잘 되게 문서 쓰기
1. 문서 하나에는 하나의 주제만 담는다.
2. 제목과 섹션명을 의미 있게 쓴다. 출처 표시 품질도 좋아진다.
3. `## 증상` 섹션에 사용자가 실제로 쓰는 표현을 넣는다. 예를 들어 "웹훅은 들어오는데 다음 노드가 안 돌아요"로 검색했을 때 해당 증상 청크가 1위로 검색되었다(유사도 0.715).
4. 긴 문단보다 짧은 절차와 번호 목록을 쓴다.

## 절차: 설정 변경
1. `.env`에서 `CHUNK_SIZE`, `CHUNK_OVERLAP` 값을 수정하고 저장한다.
2. `docker compose up -d`로 서비스를 다시 기동한다.
3. `ingest-documents`로 문서를 다시 적재한다(OP-005).
4. 같은 질문으로 검색 결과가 좋아졌는지 비교한다.

## LLM 컨텍스트 길이
- Ollama 컨텍스트 길이는 `docker-compose.yml`의 기본값 8192로 설정되어 있다(`OLLAMA_CONTEXT_LENGTH`, `.env`에 값을 적으면 그 값이 우선).
- 기본값 4096에서는 검색 청크, 로그, 프롬프트가 넘칠 때 오류 없이 앞부분이 잘린다. 검색 결과 수나 청크 크기를 늘리면 이 한도를 함께 고려한다.

## 확인 방법
- 대표 질문 몇 개로 검색해 기대한 문서와 섹션이 상위에 나온다.
- 적재 결과의 `chunkCount`가 설정 변경에 맞게 달라진다.

## 주의사항
- 청크 설정을 바꾸면 전체 재적재가 필요하다.
- 임베딩 모델을 바꾸면 반드시 전체 재적재한다. 모델이 다르면 벡터가 호환되지 않는다.
